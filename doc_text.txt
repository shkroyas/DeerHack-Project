HOW IT IS SOLVED BankSentinel never relies on any signature for its primary detection path. The Flow Agent's Isolation Forest is trained exclusively on the bank's own historical normal traffic — it has no knowledge of what an attack looks like, only what normal looks like. Any deviation triggers an anomaly score. The Behavior Agent's BiLSTM autoencoder is trained only on normal behavioral sequences; a sequence it cannot reconstruct well is anomalous by definition. Neither model has ever seen an attack signature. This means novel attack techniques — techniques that have never been observed anywhere — are still detectable because they deviate from normal, regardless of whether they match any known pattern. C4   Encrypted TLS 1.3 Traffic "The ubiquity of TLS 1.3 means payload inspection is infeasible; threats must be identified from connection metadata and TLS handshake fingerprints." HOW IT IS SOLVED BankSentinel uses a three-layer defence that works entirely without decryption. Layer 1 matches JA3 hashes against a live threat database of 14,200+ known-malicious fingerprints refreshed every 30 minutes from abuse.ch. Layer 2 is the critical addition over the original paper design: JA3S bidirectional correlation. Even if a client JA3 is not in the threat database — meaning the attacker is using a novel client implementation — a malicious server JA3S response (as seen in Cobalt Strike Malleable C2 profiles) triggers a medium-confidence alert. The server fingerprint is harder for the attacker to randomise. Layer 3 catches true zero-day TLS where neither JA3 nor JA3S is known. Legitimate HTTPS browsing has high inter-arrival time variance because humans click unpredictably. C2 beaconing has very low IAT variance because malware calls home on a schedule. Flow entropy and IAT variance scoring detect this timing pattern even for a brand new, never-before-seen TLS fingerprint.
